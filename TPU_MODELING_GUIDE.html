sysa_backhand TPU 建模指南

本项目已有可综合的 16×16 streaming systolic TPU。RTL 在 src/tpu_stream_top.sv，数值参考模型在 model/tpu_reference.py。

建模边界：当前 tpu_stream_top 只有配置、A/B 输入流和结果流，没有 CPU/总线端口。因此先固定 RTL 的数值语义和数据流，再增加 CPU 指令或 MMIO 适配层。

1. 当前 TPU 合同

项目定义
阵列16×16 output-stationary PE array
计算INT8：每 PE 每周期一个 MAC；INT4：每 PE 两个 4×4 MAC
规模M/N/K tiling，支持 64×64 及更大 GEMM
输入两个 128-bit ready/valid activation/weight stream
输出32-bit signed，tile-major、tile 内 row-major
背压m_result_ready 控制，data/valid/last 必须稳定

2. 运行参考模型

cd /path/to/sysa_backhand
python3 model/tpu_reference.py --self-test

它覆盖 INT8、INT4、odd-K、边界 tile 和 RTL 输出顺序，但不模拟周期、stall、综合结构或物理延迟。

3. 四层模型

  1. Reference：验证数值和打包规则。
  2. Stream：加入 128-bit packet、tile loader、ready/valid 和 backpressure。
  3. SystemC：加入 DMA、command queue、MAC latency 和内存带宽。
  4. CPU/system：增加 CPU 可见的 MMIO 或自定义指令，再接入 NEMU/gem5。

4. CPU 到 TPU 的接口建议

建议先加 command adapter，不改动 PE 阵列：

寄存器作用
CMD_BASE命令描述符地址
A_BASE/B_BASE/C_BASE输入和结果矩阵地址
DIMSM/N/K 与 precision
DOORBELL启动 TPU
STATUSbusy/done/error
IRQ完成中断

NEMU 先建模寄存器语义，SystemC 再建模 DMA 和周期，真实 RTL 最后接入同一命令协议。

5. 验证顺序

  1. 运行 reference self-test。
  2. 从 tb/tb_tpu_stream_top.sv 复用测试数据和 tile 顺序。
  3. 写 packet-level model，比较 A/B packet 与 output packet。
  4. 建立 SystemC DMA → tile buffer → systolic array → serializer。
  5. 逐项比较 reference、SystemC、RTL。
  6. 最后定义 NEMU MMIO/custom-0 指令。

6. 现有验证入口

cd tb
make all                 # 需要 VCS
cd ..
TPU_ACCUM_MODE=1 TPU_RUN_TAG=e3_result_q4_serializer_a1 \
  genus -batch -files synthesis/scripts/syn_genus.tcl \
